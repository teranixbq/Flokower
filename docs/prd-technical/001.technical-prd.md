# 001. Technical Product Requirements Document - Flokower App

## 📋 Project Overview

**Product Name:** Flokower  
**Description:** Mobile inventory and sales management system for UMKM florists  
**Target Users:** Flower bouquet business owners (e.g., Bucket Kreatif)  
**Platform:** iOS & Android (Mobile App)  
**Design Style:** Minimalist Black & White Bento Grid UI  

---

## 🎯 Core Features (MVP)

### 1. Authentication System
- **Email + OTP Verification**
- Secure login/registration flow
- Session management
- No complex role-based access (single user focus for MVP)

### 2. Material Management
- CRUD operations for raw materials
- Units: "lembar" or "tangkai" only
- Stock tracking with soft reservation system
- Adjustment history logging
- Low stock threshold warnings

### 3. Product Management  
- CRUD operations for flower bouquets/products
- Price management with historical tracking
- Standard ingredient mapping (default materials)
- Custom ingredient override capability per transaction
- Automatic activation/deactivation based on stock availability

### 4. Transaction System
- Create new orders from products
- Real-time stock validation before order creation
- Status workflow: `in_progress` → `completed` | `cancelled`
- Soft stock deduction when in_progress
- Final stock deduction only on completion
- Cancel action does NOT manipulate stock
- Support for multiple concurrent in-progress orders
- Manual material override per transaction

### 5. Dashboard & Metrics
- Bento grid layout for quick metrics overview
- Real-time metrics:
  - Total active products
  - Total materials stored
  - Low stock alerts count
  - Revenue today
  - Best performing product (this week/month)
  - In-progress orders count
- Recent transactions list (last 5 default)
- Floating Action Button (FAB) for quick order creation

### 6. Reports & Analytics
- Sales history with date/status filters
- Summary metrics:
  - Total revenue
  - Weekly growth percentage
  - Order statistics
- Transaction list with detail view
- Excel export functionality (.xlsx format)

### 7. Notifications & Reminders
- Push notifications for orphaned in-progress orders
- Reminder schedule at:
  - 2 hours after creation
  - 12 hours after creation
  - 24 hours (auto-cancel warning)
- Dashboard highlighting long-running orders
- Auto-cancel feature for orders exceeding 48 hours

### Database Schema

#### Materials Collection
```javascript
{
  id: string,              // Unique material identifier
  name: string,            // e.g., "Mawar Merah", "Daun Pakis"
  unit: "lembar" | "tangkai",  // Enum: leaf OR stem
  currentQuantity: number, // Current physical stock
  reservedQuantity: number,// Reserved for in-progress orders
  initialQuantity: number, // Starting baseline count
  totalAdditions: number,  // Sum of all additions
  totalDeductions: number, // Sum of all deductions (production)
  createdAt: Timestamp,
  updatedAt: Timestamp
}
```

#### Products Collection
```javascript
{
  id: string,              // Unique product identifier
  name: string,            // e.g., "Teddy Bear Bouquet"
  currentPrice: number,    // Active selling price
  description: string?,    // Optional details
  isActive: boolean,       // Auto-disabled if insufficient stock
  standardIngredients: [   // Default material mapping
    { 
      materialId: string, 
      quantityNeeded: number 
    }
  ],
  priceHistory: [          // Historical price changes
    {
      amount: number,
      effectiveDate: Timestamp,
      previousAmount: number,
      changedBy: string,
      reason: string?
    }
  ],
  createdAt: Timestamp,
  updatedAt: Timestamp
}
```

#### Transactions Collection
```javascript
{
  id: string,              // Unique transaction identifier
  productId: string,       // Reference to product
  productName: string,     // Snapshot copy
  productPriceAtSale: number,  // Snapshot at transaction time
  quantity: number,        // How many pieces ordered
  totalAmount: number,     // Calculated: price × quantity
  status: "in_progress" | "completed" | "cancelled",
  customerInfo: {          // Optional customer details
    name?: string,
    phone?: string,
    notes?: string
  },
  useCustomMapping: boolean,    // Whether custom ingredients used
  customIngredients: [          // Only if useCustomMapping = true
    {
      materialId: string,
      quantity: number,
      note?: string
    }
  ],
  orderDate: Timestamp,        // When created
  startedAt: Timestamp?,       // When moved to in_progress
  completedAt: Timestamp?,     // When marked completed
  cancelledAt: Timestamp?,     // When cancelled
  cancelledReason?: string,    // Reason for cancellation
  createdBy: string            // User ID
}
```

#### StockAdjustments Collection
```javascript
{
  id: string,                    // Unique adjustment identifier
  materialId: string,            // Which material adjusted
  adjustmentType: "addition" | "removal" | "correction",
  quantityChange: number,        // Positive (+) or negative (-)
  previousQuantity: number,      // Before adjustment
  newQuantity: number,           // After adjustment
  reason: string,                // Why the adjustment
  performedBy: string,           // User who performed it
  relatedTransactionId?: string, // If linked to a transaction
  createdAt: Timestamp           // When made
}
```

## 🔐 Security Rules (Firestore)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Helper function
    function isAuthenticated() {
      return request.auth != null && request.auth.token.email != null;
    }
    
    // Materials collection
    match /materials/{materialId} {
      allow read: if isAuthenticated();
      
      // Prevent negative quantities
      allow write: if isAuthenticated() && 
        request.resource.data.quantity >= 0 &&
        request.resource.data.unit in ['lembar', 'tangkai'];
        
      // Update must not make quantity negative
      allow update: if isAuthenticated() && 
        request.resource.data.quantity >= 0;
    }
    
    // Products collection
    match /products/{productId} {
      allow read: if isAuthenticated();
      
      allow write: if isAuthenticated() && 
        request.resource.data.price >= 0 &&
        request.resource.data.isActive in [true, false];
    }
    
    // Transactions collection
    match /transactions/{transactionId} {
      allow read: if isAuthenticated();
      
      allow create: if isAuthenticated() && 
        request.resource.data.status == 'in_progress' &&
        request.resource.data.quantity > 0;
      
      // Only transition from in_progress to completed/cancelled
      allow update: if isAuthenticated() &&
        (resource.data.status == 'in_progress' && 
         request.resource.data.status in ['completed', 'cancelled']) ||
        (resource.data.status == 'pending' && 
         request.resource.data.status == 'in_progress');
         
      // Validate no duplicate completions
      allow update: if !request.resource.data.status.equals(resource.data.status);
    }
    
    // Stock adjustments collection
    match /stockAdjustments/{adjustmentId} {
      allow read, write: if isAuthenticated() &&
        request.resource.data.quantityChange >= 0 ||
        request.resource.data.adjustmentType == 'removal';
    }
  }
}
```

## 🛡️ Business Logic Rules

### Rule 1: Stock Validation Before Order Creation
```javascript
Function: canCreateOrder(product, availableStock)
Input: Product object, Material stock data
Output: Boolean (true = can proceed, false = insufficient stock)

For each ingredient in product.standardIngredients:
  Get corresponding material data
  Calculate available = material.currentQuantity - material.reservedQuantity
  
  If available < ingredient.quantityNeeded:
    Return FALSE
    
Return TRUE
```

### Rule 2: Soft Stock Reservation
```javascript
Function: reserveStock(transaction)
Triggered when order status = 'in_progress'

For each ingredient in transaction.ingredients:
  Get corresponding material
  material.reservedQuantity += ingredient.quantityNeeded
  Update material document in Firestore
```

### Rule 3: Final Stock Deduction (On Completion)
```javascript
Function: completeTransaction(transactionId)
Requires: Firestore runTransaction() for atomicity

Within transaction scope:
  1. Get transaction data
  2. Verify status = 'in_progress'
  
  For each materialUsage in transaction.materialsUsed:
    Get material reference
    newQuantity = material.currentQuantity - materialUsage.quantity
    reservedQty = material.reservedQuantity - materialUsage.reservedQuantity
    
    Update material:
      currentQuantity = newQuantity
      reservedQuantity = reservedQty
      updatedAt = serverTimestamp()
  
  Update transaction:
    status = 'completed'
    completedAt = serverTimestamp()
```

### Rule 4: Cancel Operation (No Stock Change)
```javascript
Function: cancelTransaction(transactionId)
Requirements: status must be 'in_progress'

Action:
  1. Release reserved quantities
  2. Mark transaction as cancelled
  3. Set cancelledAt timestamp
  4. Optionally capture cancellation reason

Note: NO deduction occurs on cancel
```

### Rule 5: Auto-Disable Product on Low Stock
```javascript
Function: checkProductAvailability(product, allMaterials)
Triggers on: Material update or Product creation

For each ingredient in product.ingredients:
  Get material data
  If material.currentQuantity < ingredient.quantityNeeded:
    Set product.isActive = FALSE
    Break loop

Save product with updated status
```

### Rule 6: Prevention of Negative Stock
```javascript
Layer 1: Client-side validation
- Check before showing submit button
- Disable button if insufficient stock
- Show clear error message

Layer 2: Database security rules
- Enforce quantity >= 0 constraint
- Reject any update that results in negative

Layer 3: Server-side verification
- Post-deduction validation check
- Rollback if negative detected
- Alert admin immediately
```

### Rule 7: Duplicate Click Prevention (Loading State)
```javascript
UI State Machine:
  IDLE → Loading → Success/Error

Transitions:
  Click button (IDLE):
    - Set isLoading = TRUE
    - Disable button
    - Show loading spinner
    
  API Response (Loading):
    On success:
      - Set isLoading = FALSE
      - Set isSuccess = TRUE
      - Show "Completed" state
      
    On error:
      - Set isLoading = FALSE
      - Set isError = TRUE
      - Show retry option
  
  Re-click during LOADING:
    - Ignored (button disabled)
```

### Rule 8: Orphaned Order Detection
```javascript
Function: cleanupOrphanedOrders()
Schedule: Daily background job

CutoffTime = Now() - 48hours

Query: Find all orders where
  status = 'in_progress' AND
  startedAt < CutoffTime

For each orphaned order:
  Send push notification reminder
  Schedule auto-cancel after 24h warning
  Highlight in dashboard
```

## 📊 Performance Considerations

### Optimization Strategies
- Use Firestore offline persistence for reliability
- Index common query fields (status, date, product_id)
- Limit document sizes (store only essential fields)
- Implement pagination for large lists (>100 items)
- Batch writes for bulk updates
- Cache dashboard metrics for 5-minute intervals

### Monitoring Points
- App cold start time (<2 seconds target)
- Screen transition smoothness (60fps target)
- Network latency impact on user experience
- Battery consumption during heavy usage
- Storage size growth over time
